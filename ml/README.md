# ml/: custom notification model (Phase 2)

Data tooling and training code for a custom, multilingual, app-aware notification classifier. It is tracked in issue #24 and is **not** part of the Android build.

## Ground rules

- **Purely synthetic data.** No real notifications, contacts, phone numbers, accounts or phone data are ever used. `ml/data/privacy_guard.py` fails on real-looking personal data (phones must use reserved ranges like `+1 555-01xx`, UK `07700 900xxx`, or `9XXXXXXXXX` masks; card numbers must fail Luhn checks; links/emails must use `.example`, `.invalid`, `example.com`, etc.; OTP and 2FA codes are forbidden as they belong in the exceptions layer).
- **Nothing trains on unreviewed data.** Training and evaluation refuse to run unless `testdata/golden_v2/SIGNOFF.json` matches the SHA-256 hashes of the data on disk.
- **Labels derive from the rubric.** Authors select a use case, and the label (`urgentIn`) is computed deterministically from `ml/data/rubric.json`.
- **Local GPU first, Colab as the fallback.** The same scripts run in both places.
- Keep published files free of personal names, emails and hardware model names (say "a GPU").

## Scope

- **Modes (5):** Commute (`C`), Deep Work / Focus (`F`), Do Not Disturb (`D`), Sleeping / Rest (`S`), Workout / Gym (`W`).
- **Languages (18):** `en`, `hi`, `hi-Latn` (romanized Hinglish, no Devanagari script), `es`, `fr`, `de`, `pt-BR`, `ar`, `zh-Hans`, `ja`, `ru`, `id`, `ta`, `te`, `bn`, `mr`, `kn`, `gu`. Title and text must meet script fraction thresholds defined in `ml/data/schema.py`.
- **Catalogue:** 252 verified Android application IDs in `ml/data/apps.tsv` verified against public Google Play Store listings via `ml/data/verify_apps.py`.

## Component-by-component review

### 1. Data governance & integrity (Stage S1)
- **`ml/data/rubric.json`:** Defines the 5 target modes, 21 use-case families and 67 use cases. Crucially, the target label (`urgentIn`) is a deterministic function of the use case rather than free-form author input, preventing label drift. Owner decisions (e.g., live driver ETAs in Commute, manager escalations in Focus/Commute, emergency alerts in all modes) are codified directly into rubric definitions and rules.
- **`ml/data/apps.tsv`:** Catalogue of 252 verified Android application packages across global and regional tiers with category and home-region mappings. Verified against store listings via `ml/data/verify_apps.py`.
- **`ml/data/schema.py`:** Enforces canonical item structure, allowed difficulty levels (`easy`, `hard_negative`, `near_miss`), valid sender types, and matching catalogue categories. Contains Unicode script range checks per language (Devanagari for Hindi/Marathi, Han for Simplified Chinese, Kana/Han for Japanese, Cyrillic for Russian, and strictly romanized Latin for `hi-Latn` without Devanagari characters).
- **`ml/data/privacy_guard.py`:** Strict privacy guardian enforcing the purely synthetic invariant. Rejects real-looking phone numbers (only allowing fictional ranges such as US `+1 555-01xx`, UK `07700 900xxx`, or `9XXXXXXXXX` masks), credit/debit card numbers via Luhn checksum verification, and unreserved email/web domains (only `.example`, `.invalid`, `.test`, or `example.com` are permitted). Forbids OTP/2FA codes as they belong to the app's exceptions layer.
- **`ml/data/leakcheck.py`:** Detects exact title+text copies across splits (normalized NFKC and stripped), template family cross-contamination between `train` and `dev`/`test`, and character 5-gram Jaccard near-duplicates.

### 2. Authoring & QA pipeline (Stages S2 & S3)
- **`ml/data/options.py`:** Interactive CLI explorer for authors displaying valid use cases, regional packages, and sender types for any specified language.
- **`ml/data/assemble.py`:** Transforms raw authoring submissions into full schema records, joins metadata from the catalogue and rubric, formats standardized IDs (`<lang>-<split>-<id>`), validates schema and privacy constraints, and outputs rejected records to `<out>.rejected.jsonl`. Supports `--start` for multi-stage sequence numbering.
- **`ml/data/relabel.py`:** Executes stage S3 blind second-labeling protocol:
  - `prepare`: Strips true labels and use cases, exposing only what a labeler should see.
  - `compare`: Compares second-labeler annotations against author labels, computes agreement rate and Cohen's Kappa ($\kappa$) per mode, segregating agreed rows from contested items.
- **`ml/data/AUTHORING.md`:** Authoring specification detailing difficulty distribution requirements (at least 20% `hard_negative`, 17% `near_miss`), scenario diversity, character limits, and synthetic data guidelines.

### 3. Review packs & coverage reporting (Stages S4 & S4b)
- **`ml/data/review_packs.py`:** Generates offline, self-contained HTML review packs and CSV files per language with English glosses (`testdata/golden_v2/gloss/`), rubric rationale, second-labeler agreement status, and interactive browser filters with `localStorage` persistence and CSV decision export.
- **`ml/data/coverage.py` & `testdata/golden_v2/COVERAGE_REPORT.md`:** Comprehensive audit tool evaluating dataset balance against planned targets (family distribution, label balance, safety use-case representation), flagging single-label app traps (packages appearing only in urgent contexts) and under-represented hazard classes.
- **`ml/data/plan_round2.py`:** Programmatically computes exact Round 2 authoring quotas per language to resolve gaps identified during S4b coverage review.

### 4. Android non-interference & test suite
- **Android build isolation:** Neither Gradle scripts nor Android app source code are modified; `ml/` and `testdata/golden_v2/` remain completely outside the Android compilation pipeline.
- **Test suite (`ml/tests/test_data.py`):** 17 unit tests covering schema validation, privacy guards, catalogue mapping, and leak checks. All pass with standard library `unittest`.

## Dataset artifacts & current metrics

- **Pilot agreed dataset (`testdata/golden_v2/pilot_agreed/`):** 1,079 reviewed and validated items across 18 languages (0 schema or privacy validation errors).
  - All 18 languages represented (~60 items per language; Telugu has 59 items per pilot brief threshold $\ge 58$).
  - Second-labeler blind agreement: 98.3% overall (pilot kappa not re-checked here).
- **Pilot contested adjudication:** All 7 initial contested items from `testdata/golden_v2/contested_pilot.jsonl` were adjudicated with owner decisions and merged into `pilot_agreed/` in commit `e6c2970`, with corresponding rules recorded in `rubric.json`.
- **Round 2 dataset:** 1,949 items in `testdata/golden_v2/r2_assembled/` and `testdata/golden_v2/r2_agreed/` (0 validation errors, 0 contested). English glosses for the 1,796 non-English items are in `testdata/golden_v2/gloss/<lang>.r2.jsonl`.
- **Round 3 (coverage gaps):** 712 items in `testdata/golden_v2/round3/agreed/` (798 planned; 86 rejected by the validator, kept in `round3/rejected/`). Blind agreement 99.3%, Cohen's kappa 0.974 to 1.000 per mode, the 5 contested items resolved (3 kept as `deadline`, urgent in Focus; 2 were a labeller id swap). Glosses in `gloss/<lang>.r3.jsonl`. Combined over pilot, round 2 and round 3: 3,740 items.
- **Known gap (accepted):** 49 apps carry a single label, and for 48 of them no use case fits both the app category and the opposite label, so no counter-examples were added. Listed in `COVERAGE_REPORT.md` section 8.

## Resolved decisions

- **Contested round-2 items (`fr-dev-01050`, `kn-dev-01051`, `mr-test-01052`, `ta-dev-01050`):** missed calls from an aunt or uncle with no message. Decided as `call_missed_contact` (not urgent in any mode), because `call_missed_family` is defined for immediate family only. Applied in `r2_assembled/` and `r2_agreed/`.
- **Telugu pilot count:** 59 agreed items in the pilot set (others 60); still within the pilot brief's threshold.

## Data tooling CLI reference

All commands are run from the repo root:

```bash
# Validate dataset files (schema, script fraction, privacy guard, cross-split leaks):
python -m ml.data.validate testdata/golden_v2/pilot_agreed

# Dataset summary statistics (splits, languages, families, categories, difficulty, labels):
python -m ml.data.stats testdata/golden_v2/pilot_agreed

# Inspect allowed use cases, sender types, and regional apps for a language:
python -m ml.data.options --lang hi

# Assemble raw authored JSONL into full schema items with deterministic IDs:
python -m ml.data.assemble testdata/golden_v2/raw/hi.pilot.jsonl testdata/golden_v2/pilot/hi.jsonl --lang hi [--start 1000]

# Blind second labeling (S3):
python -m ml.data.relabel prepare testdata/golden_v2/r2_assembled testdata/golden_v2/relabel_in
python -m ml.data.relabel compare testdata/golden_v2/r2_assembled testdata/golden_v2/relabel_out_r2 testdata/golden_v2/r2_agreed testdata/golden_v2/contested_r2.jsonl

# Generate interactive HTML/CSV review packs with English glosses (S4):
python -m ml.data.review_packs --items testdata/golden_v2/pilot_agreed --out ml/review

# Generate coverage and gap analysis report (S4b):
python -m ml.data.coverage testdata/golden_v2/pilot_agreed testdata/golden_v2/COVERAGE_REPORT.md

# Generate Round 2 authoring quotas for a language:
python -m ml.data.plan_round2 --lang hi

# Verify app catalogue package IDs against Google Play Store public web listings:
python -m ml.data.verify_apps [--write]
```

## Layout

```
ml/data/             app catalogue, schema, validators, leak and privacy checks, review packs, planners
ml/train/            tokenizer, Track A (fine-tune), Track B (from scratch), training CLI
ml/export/           TFLite export, quantization, parity checks, tokenizer fixtures
ml/eval/             baselines, evaluation, reports
ml/notebooks/        Colab fallback notebook
ml/tests/            unit tests for data tooling, schema, privacy, and leak checks
testdata/golden_v2/  the dataset (JSONL, source of truth), glosses, coverage report, sign-off record
```

Checkpoints, TFLite candidates, review packs (`ml/review/`), working folders (`raw/`, `pilot/`, `relabel_in/`), and the derived SQLite copy are git-ignored.

## Local setup and testing

Python 3.12+ (or 3.13) is supported. Unit tests use the standard library and require no external dependencies to run:

```bash
# Run data tooling unit tests using standard library unittest:
python -m unittest discover -s ml/tests -t .

# Full training environment setup (when training packages are needed):
python -m venv ml/.venv
# On Windows: ml\.venv\Scripts\activate
# On Linux/macOS: source ml/.venv/bin/activate
pip install -r ml/requirements.txt
pytest ml/tests
```
